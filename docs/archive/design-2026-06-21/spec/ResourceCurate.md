# 资源增补 ResourceCurate —— 深度规格

> 真实文件:`src/pages/ResourceCurate.jsx` · 路由 `/resources/curate`(从协作页入口进)

## 为什么有这一页

协作页有「资源增补」入口,点进来就是**这张提交表单**。用户推荐一条书目/课程链接,审核通过后并入资源页书架。没有它,那个入口是死的。

## 结构

1. 顶部页头 + 返回协作。
2. 报头(居中):眼标「Curation de ressources」→ h1「推荐一条资源」→ 说明。
3. **表单态**(四字段):
   - 标题 · Titre(文本)
   - 链接 · Lien(url)
   - 归入书架 · Rayon(下拉,选项 = 资源页的 8 个书架 I–VIII)
   - 推荐理由 · Pourquoi(多行)
   - 「提交待审 · Proposer」+ 取消 + 一句「提交后由管理员审阅」说明。
4. **已提交态**:绿 ✓「已提交」+ 「再推荐一条 / 回到协作」。
5. **未登录态**:提示登录。

## 关键细节

- 书架下拉的选项**必须与资源页 `resourceCatalog.js` 的 8 个书架一致**(I 数学分析…VIII 计算排印)—— 这样审核通过能直接并入对应架。
- 提交是**进待审队列**,不是直接上线(文案已说明「由管理员审阅」)。审核在被删的 ModerationCenter?不——协作已收敛,审核逻辑接 Supabase 即可,无需独立审核中心页。
- 字段 `中文 · Français`,零英文。
- 真实化:写入 Supabase 待审表(anon key + RLS);校验链接是 URL、标题非空。

## 易错点

- ❌ 书架选项和资源页对不上 → 必须一致。
- ❌ 提交直接上线 → 进待审队列。
- ❌ 漏未登录态 → 需登录才能提交。
